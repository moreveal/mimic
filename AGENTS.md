# Работа над Mimic

- Оптимизируй измеренные архитектурные затраты. Перед новым классом изменений снимай свежие профили; не останавливайся на произвольном пороге времени. Эталон — frozen Chrome 152.
- Не меняй frozen harness, workloads и исходный baseline. Перед каждым benchmark проверяй и записывай SHA-256 запускаемого файла против только что собранного бинарника; несовпадение — немедленная остановка.
- Для итераций используй `tools/performance/fast_gate.py`: DOM/static/React warm ×5, static N=10/25 ×3, память после 10 Pages. Проверки корректности обязательны; полную матрицу запускай после группы существенных изменений.
- Сохраняй каноническую DOM identity, семантику и один event loop на Page. Независимые Pages не должны сериализоваться глобальным runtime lock. Не добавляй Web APIs ради оптимизации.
- Учитывай память, throughput и удержание после teardown вместе с задержкой. Оформляй изменения отдельными коммитами с дельтами и регрессиями; актуальные результаты и ограничения — в `docs/performance/report.md`. Rust spike веди отдельно, с теми же нагрузками и критериями корректности.
