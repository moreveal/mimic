# Cached module-error ownership correction

Final review found an ownership error in the v2 dynamic-import cleanup: an incoming completion error can be the module graph's cached native SyntaxError. Releasing that error after the first import invalidated the graph's root, so subsequent or concurrent imports could remain unresolved. The new regression fails on the v3 base with `context deadline exceeded` after four seconds ([before-fix failure](data/optimization-20260914/module-error-ownership/before.txt)).

The fix releases only an error produced by the completion's own EvalModule operation. An incoming error remains borrowed from the graph. The engine completion contract now documents that ownership. Existing resolver/evaluation temporary cleanup stays in place.

Chrome 152.0.7977.82 was executed against the same invalid module through HTTP. Concurrent and later imports all reject with the same SyntaxError object, and the module is fetched once. The oracle observed `concurrent, first, cached` for the initial load and `first, concurrent, cached` after caching; the [four-iteration oracle](data/optimization-20260914/module-error-ownership/chrome152.json) and [executed source](data/optimization-20260914/module-error-ownership/oracle.js) are retained. The focused regression checks identity, name, one network request, both concurrent rejections before the later awaited cached import, timeout protection, and no additional roots after the first cached error owner is created. It does not claim that the existing independent module wait goroutines reproduce the exact order between the first two concurrent completions. That ordering remains a separate known limitation; this ownership fix changes no queue policy.

Patch: `handles-module-error-fix.patch`, SHA256 `07b85e0067540d9aff2012bc90d82cdac57856c1f598dea217bf6c93327ee526`. Windows focused module regression suite passed in 1.476 s ([Windows validation](data/optimization-20260914/module-error-ownership/windows-focused.txt)), Linux race passed in 4.079 s ([Linux race validation](data/optimization-20260914/module-error-ownership/linux-race.txt)). These are validation durations, not performance comparisons. This fix affects invalid/cached module failures, which were not used in the earlier six-scenario performance sample or the hybrid control/candidate base. Final production must include the correction; it must not reapply the older blanket incoming-error release.
