## Remaining concrete branch difference

HDEX5/Aqcaj8 reproduce the previously localized RTC helper-cache lifetime branch.
These labels are not MIME-support flags. The prior reduction established a
5000 ms cleanup: use the live cached peer or take the fallback after cache expiry.
In new Mimic trace A, the child helper createOffer access is at
12:11:42.5438057Z and its close access at 12:11:47.8324903Z: 5288.685 ms later.
A later iceGatheringState read occurs at 12:11:50.6168973Z. Both repeats yield the
same cache-result difference. These accesses and result fields support the known
deadline explanation; this turn did not re-instrument the exact internal cache
read/write instructions. See `docs/compatibility/media-completion-20260912.md`.

The last XqEQ3 component also samples a different asynchronous completion state:
Chrome's video result is still null, while Mimic has the finished array. The
other three capability arrays match. This agrees with the previously established
decoder completion race; it does not establish a new unsupported codec.

Notification profile values differ: denied in Chrome, default/prompt in Mimic.
Other permission names/states in that result now agree. Graphical capability
lists, selected GPU/context attributes, software raster/geometry observations
and environment values remain different. Their unequal outputs alone do not
prove a new exception path or identify every downstream predicate.

The child selector-observation sequence matches completely (34 entries). Parent
sequences include dynamic widget IDs and varying repeated frame queries; they
are not byte-equal across Chrome controls, so this is not a demonstrated new
stable reentry defect.
