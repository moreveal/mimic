# Расхождения VM из manual-20260912-012501

Сравнение выполнено 12 сентября 2026 года. Расхождения есть **за пределами
таблицы наличия API**: отличаются результаты отдельных проверок программы,
геометрия, сериализация, наблюдаемые внутренние вызовы и незавершённые операции.
Исправления runtime в рамках этой работы не вносились.

## Источники и воспроизводимость

- Вход: `compatibility/private-captures/manual-20260912-012501`, 39 сохранённых
  ответов. Исходный capture не содержит проверяемого паспорта сборки; его нельзя
  автоматически приписывать текущему HEAD.
- Свежие сборки Mimic: чистый `1e4ce25ff5c37294b94e4222792e195ff65c82ea`, V8,
  Windows amd64, Go 1.26.4. Хеши и buildInfo сохранены с результатами.
- Новый контроль на **тех же сохранённых программах**: frozen Chrome
  **152.0.7977.82**, Chromium `d04cdb24d67b081f6cf80200ffc5233f44b61109`,
  V8 `15.2.124.21`, headful. SHA256 Chrome:
  `ea36dd818a90176f1a70616f0363d9be527229389a6c073a0b1688b9e73f67e9`.
- Использованы инструкции `AGENTS.md`, `docs/oracle-policy.md`, README
  occurrence-aware offline replay и README локального `cf-vm-lab`.
- Все приватные материалы этой работы: `.build/analysis-012501/`.
  `receipt.json` содержит хеши основных результатов;
  `all-payload-diffs.json` — полный список различий входов сериализатора;
  `stage-summary.json` — каждый исследованный блок и устойчивость его полей.

Старые Chrome captures найдены вместе с предыдущими исследованиями, но они
содержат другие серверные программы. Поэтому для этого сравнения сделаны новые
Chrome A/B на входных данных 012501. На целевой сайт запросы не отправлялись:
Mimic использует только replacement transport, Chrome — сохранённые ответы,
отклоняющий внешний трафик proxy и ограничения DNS/UDP. ICE-кандидаты Mimic
формируются из Environment; их присутствие в payload не означает реальный STUN.

## Что прочитано и какой путь пройден

Из исходного orchestration JS извлечён встроенный VM-кандидат размером 4522 байта.
Для child-интерпретатора разрешены 4816 ссылок на строковую таблицу из 1926 строк;
результат — `child-readable.js`. Ответы `/fo/` декодированы алгоритмом из самой
программы, исходные capture-файлы сохранены без изменений.

| Ответ, индекс с нуля | Назначение по пути выполнения | Размер декодированного bytecode |
|---|---|---:|
| 3 / 20 / 35 | Parent continuation, циклы 1 / 2 / 3 | 63730 / 63728 / 63730 |
| 8 / 23 / 38 | Основные child-программы | 475733 / 462774 / 462727 |
| 13 / 28 | Child continuation после отправки результатов | 2879 / 2836 |
| 14 / 29 | Parent continuation | 1821 / 1821 |

Это декодирование и исследование наблюдаемого пути, **не полный линейный
дизассемблированный листинг всех инструкций**. Операнды, переходы и rolling key
зависят от выполнения; нельзя приписывать непосещённым ветвям поведение.

Для сравнения инструментированы шесть сериализаторов в сохранённых ответах.
Каждый из двух прогонов Chrome и двух прогонов Mimic дал **10 полных пар
input/output**. Во всех четырёх прогонах все десять output побайтно совпали с
последующим POST body. Снимки не обрезаны, ошибок разбора нет. Это связывает
различающиеся значения с реально сформированными отправлениями.

В первом большом child-payload находятся 39 пронумерованных блоков результатов,
во втором — 38. Поля результата различаются в 23/39 и 22/38 блоках соответственно,
даже если не учитывать общие поля начала/конца/длительности блока. Эти числа
включают окружение, производительность и диагностику, **не являются числом
независимых дефектов**. Номера блоков между циклами меняются; сравнивать нужно
назначение/поля, а не одинаковый номер из разных программ.

Неинструментированный Mimic и оба инструментированных прогона проходят два
полных обмена и начало третьего. Остановка — первый отсутствующий в capture GET
третьего цикла после fixture 38, а не успешное окончание всей третьей программы.
Mimic делает 29 обращений к transport; неиспользованным остаётся favicon fixture
6 из-за cache. Chrome достигает той же отсутствующей `/pat/` операции.
Различия количества fixtures нельзя считать различиями числа VM-шагов:
Critical-CH, cache и синтетические ресурсы обрабатываются разными слоями.

## Подтверждённые локальными проверками расхождения

Тестовая логика находится в `.build/analysis-012501/probe.js`.
Фактические результаты относительно этого каталога находятся в
`focused/chrome-a.json`, `focused/chrome-b.json`, `focused/mimic-before.json`.
Два Chrome-контроля совпали полностью; сравнение с Mimic дало 21 структурное
различие. Ни одна из восьми независимых проверок не прервала остальные:
ожидаемые исключения записаны внутри соответствующей проверки.

| Область | Frozen Chrome | Mimic | Связь с сохранённой VM |
|---|---|---|---|
| HTML-сериализация кавычек | `<div data-foo="&quot;"></div>` | `<div data-foo="&#34;"></div>` | `OjmeV1[86]` и `[104]`, блоки 38 / 7. Одинаковая DOM-семантика не делает строки равными. |
| Внутренние обращения к публичному selector API | Чтение select options/length/selectedIndex/value и document collections не вызывает авторский `querySelectorAll` | Четыре вызова `option`; отдельные вызовы `img`, `form`, `a[href],area[href]` | Лишние записи в `maNnU6`. ## Почему старая таблица API не показывает проблему

Оба больших payload по-прежнему содержат по **1666 именованных наблюдений** в
`gsLi5`. Обратное преобразование value → имена свойств даёт только 10 различий:

- `d.baseURI`, `d.referrer`: разные динамические `/rch/` идентификаторы. Только
  этот сегмент явно заменяет replay; после его нормализации значения совпадают.
- `d.lastModified`: время разных выполнений.
- `n.webdriver`: Chrome diagnostic запускается с debugging port 0; отдельный
  fixed-port профиль не эквивалентен этому запуску.
- Четыре visibility-проекции и outerWidth/outerHeight: состояние скрытого
  диагностического окна против выбранного Environment Mimic.

Таким образом, восемь оставшихся различий этой **узкой таблицы** сами по себе
не доказывают новую общую ошибку API. Но она не включает результаты остальных
вычислений VM. Вывод прежнего отчёта о закрытом consumed service residual нельзя
расширять до равенства полного VM-payload.

## Граница вывода и дальнейшая локализация

В parent payload после обоих полных циклов **и Chrome, и Mimic** передают
`NaCW0 = "600010"`. Это продолжение сохранённых серверных ответов: сервер заново
не проверяет сформированный payload. Ни прохождение replay, ни этот код не
показывают, какое конкретное отличие приводит к отказу в живом запуске.

Instrumented Chrome A/B завершились без harness errors. Дополнительный Chrome
с Debugger использован только для извлечения источников, не как прозрачный
контроль поведения. Неинструментированный Chrome дошёл до того же capture
boundary; при закрытии контекста записана одна ошибка `Fetch.failRequest:
Session with given id not found`. Она сохранена, а не скрыта как успешный вызов.
В focused HTTP fixture был connection reset при teardown; обе Chrome-пробы и
Mimic-проба завершились с полными результатами. В Mimic остаются пять imageDecode
диагностик; это не новое доказательство причины отказа.

Приоритет для последующей работы: сначала воспроизводимые selector reentry,
HTML/nonce и координаты; затем расшифровка индексов `IGBuA2/oHIQ6` и устойчивой
ветви `BMnw0/knVv1`; отдельно — заявленные, но незавершённые media/RTP/OPFS
возможности. Graphics/profile различия требуют измерения конкретных операций,
а не подстановки хеша или глобальной смены имени GPU. Изменения production,
полный regression suite и performance-прогоны в эту диагностическую работу
не входили.
