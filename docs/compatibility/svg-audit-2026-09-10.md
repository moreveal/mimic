# SVG subsystem audit — 2026-09-10

## Reference and scope

The reference is local Chrome **152.0.7977.82**, queried in an isolated browser
context against synthetic local fixtures. No challenge script, challenge value,
site-specific branch, cookie or private recording is part of the implementation
or these tests. This audit does not establish that Voxel or Cloudflare passes.

`TestSVGAuditDifferential` runs 14 new fixture families on both V8 and Goja.
The retained JSON files are under `compatibility/captures/semantic-checkpoints`;
their metadata records the native browser version, fixture path and LF-normalized
SHA-256. The existing bbox, CSS transform, text and font fallback oracles remain
separate and retain their native expectations.

The matrix, list, scalar and reflection implementations share canonical DOM
attributes and private per-realm slots. Font resources are Page-owned. There is
no render target, GPU requirement, native graphics backend or command-history
fingerprint used to synthesize these values.

## Accuracy and unsupported boundaries

This is broad measured coverage, **not complete SVG conformance**. Surface
agreement is not evidence that every exposed operation is implemented.

* Text advances and the captured line/character metrics compare exactly at the
  fixture's precision. Horizontal ink bounds are outline observations; Windows
  raster hinting is not reproduced. The separate font fallback test allows one
  CSS pixel only on horizontal ink edges and retains the native capture.
  `SVG.approximateTextInkBounds` identifies this limitation. Complex ligature
  carets, rotated character hit-test boundaries, full bidi and text selection
  are not fully covered by this audit. TextPath, unsupported baselines,
  textLength adjustment, missing fonts and unsupported shaping fail explicitly.
* Curved path lengths use bounded CPU subdivision, not Chrome/Skia's precise
  flattening policy. `SVG.approximatePathMetrics` records that fact. The new
  native comparison permits absolute length differences below 0.5 for its
  radius-10 circle, 0.7 for its ellipse, 0.03 for its arc, and 0.003 for its
  quadratic/cubic fixtures. These are local test bounds, not universal error
  guarantees. Line and polygon lengths are exact in the captured tests.
* Rounded-rectangle path metrics, CSS path data, dashed strokes and non-scaling
  strokes remain explicit unsupported operations. General marker/filter paint,
  clipping and raster coverage are not implemented by geometric hit tests.
* Screen CTM supports the measured root SVG/body placement and nested SVG
  transforms. General HTML flow, transformed HTML ancestors and other layout
  contexts are explicit boundaries where detected; it is not a full HTML
  layout engine. More complex CSS expression parsing is not complete.
* Use instances do not materialize a shadow rendering tree. External documents,
  referenced text/images/foreignObject, nested viewport references and
  instance-relative geometry are explicit unsupported cases. Full instance
  style inheritance and symbol sizing are not established by the basic tests.
* Animated values currently reflect static base state with a read-only animVal
  projection. There is no SMIL sampling or SVG animation timeline engine.
  Static attributes on filters/gradients/markers do not implement their paint.
* SVG style.sheet has an explicit unsupported boundary because owner stylesheet
  integration is absent. It is an implementation gap, not a GPU requirement.
  This is the one explicit getter boundary accepted in the default-attributes
  comparison; a separate test requires the exception and its diagnostic reason.
* Remaining generated SVG methods/accessors now throw NotSupportedError with
  interface/member context instead of silently returning placeholder values.
  The fallback preserves the measured descriptor and arity. This intentionally
  differs from native success until the underlying capability is implemented.
* Exhaustive cross-realm value transfers, every malformed grammar, all list
  mutation sequences, animation event scheduling and every CSS transform
  expression are not certified. Unsupported DOMMatrix CSS expression syntax
  still uses SyntaxError; the parser supports the tested numeric transform
  lists, not a full CSS expression engine.

The small Goja/Chrome trigonometric variation in the SVG matrix-operation fixture
uses an absolute 1e-14 tolerance. Other matrix fixtures explicitly round their
observations to nine decimals. Native JSON expectations have not been edited to
match Mimic.

## Reproduce

With the frozen Chrome CDP endpoint available on localhost:9343:

```powershell
python -X utf8 tools/compatibility/capture_query_oracle.py internal/browser/testdata/svg_surface_oracle.js compatibility/captures/semantic-checkpoints/svg-surface-chrome152.json --secure-context
go test ./internal/browser -run TestSVGAudit -count=1
go test ./... -count=1
go test -race ./internal/browser ./internal/textmetrics ./internal/webapi -run 'TestSVGAudit|TestFontFallback|TestSemanticBoundary|TestRealmIsolation|TestAwaitChildWorkCancellationAndPageTeardown' -count=1
go build -o .build/mimic.exe ./cmd/mimic
```

Other fixtures use the same capture command with their corresponding paths.
`svg_attribute_defaults.js` is native default/type metadata; its values feed the
live generic reflection implementation, not snapshot-returning getters. Changes
to that table must be validated against both attributes and mutation fixtures.
