# Flickr Turnstile: VM data comparison before packing

## Measurement boundary

Two **live** Flickr loads captured the VM function's argument object immediately after `XMLHttpRequest.send` for the first and second `/fo` requests. Frozen Chrome 152 obtained a token; Mimic sent both POSTs, received `600010`, and left the token field empty. These runs did not replace pixels, server responses, VM objects, or network data. This is not offline replay. Diagnostic code only read argument values and did not change production Mimic.

The successful Chrome capture was copied to the ignored `.build/flickr-audit/chrome152-success-frozen-20260926/`; sizes and SHA256 hashes were added to `receipt.json`. Raw objects, HTML, and chunks contain session data and remain outside Git. The complete local registry of leaf differences, including types, lengths, and HMACs, is `.build/flickr-audit/vm-analysis/prepack-aligned-diff-registry.json`, generated by `.build/align_flickr_prepack.cjs`. Nested object keys may themselves contain session data, so this registry remains private. The HMAC key is stored only locally.

## Comparison

The first object before POST has 50 own keys in both browsers, of which 45 appear in JSON. There are 27 differing and 40 matching leaf values. The top-level field sets match; Mimic has one additional element in `VbYF3` (3 versus 2). Other first-object differences may include timestamps, session identifiers, and profile values; they do not by themselves establish a browser API defect.

The second object before POST has 101 own keys in Chrome and 100 in Mimic; JSON exposes 90 and 89, respectively. Of these, 51 named fields occur in both. The rest are numeric blocks: 39 in Chrome and 38 in Mimic. Their order differs, making comparison by numeric index invalid. Blocks were aligned by fields beyond their common envelope: 34 pairs have unique exact signatures, three repeated empty signatures were paired by order, and one pair partially matches. One Chrome block has no counterpart.

After alignment, the second object has 768 differing and 2,359 matching leaf values. Among the 768 differences, 62 involve a missing value on one side, 8 change type, 311 have the same type but different lengths, and 387 have the same type and length but different values. These are **observed differences between two independent live sessions**, not 768 confirmed Mimic defects. Arrays inside blocks are compared by position, so reordered elements can inflate the count.

## Established cause of the Trusted Types failure

A separate diagnostic Mimic run recorded stacks for the specified `EvalError` (`.build/flickr-audit/vm-analysis/mimic-tt-stacks.json`). It also sent two POST requests and left the token field empty. Six stacks form three pairs: `navigator.gpu`, `OffscreenCanvas.getContext`, and the `OfflineAudioContext` constructor. All converge on `ensureLazyDomain` in `internal/webapi/surface.js`. There, subsystem source is loaded through `eval(host.lazyDomainSource(name))`. The iframe CSP includes `require-trusted-types-for 'script'`; its `default.createScript` policy returns an empty string for arbitrary code. `evalSourceResolver` correctly rejects that substitution, but this means **Mimic's internal code incorrectly goes through a check intended for author-supplied `eval`**. After the first failure, the lazy domain is marked `failed` and throws the same error again. Thus, at least three Web API groups become unavailable in this load before the VM builds the second object. This architectural cause could affect any document with such a CSP, not just Flickr.

The stacks connect the Trusted Types error to lazy domains. They do not prove that this alone causes every other field difference. Definitive attribution requires mapping each field to a VM operation while separately accounting for session data and time.

## Conclusion and limits

Mimic reaches the second POST, but its VM input before packing already differs structurally from successful Chrome. A general lazy-domain loading defect under CSP was established: Trusted Types blocks internal `eval`, giving the VM errors in place of some probe results. One entire block is also missing. It is not yet known which field the server checks or whether the Trusted Types failure alone causes `600010`. A causal conclusion requires connecting fields to the invoked VM functions and repeating the comparison while accounting for changing session data. Another Chrome run is unnecessary to preserve the existing successful trace.

## Fix and subsequent live verification

In `surface.js`, internal lazy-domain source is now passed to direct `eval` as a private code object. The V8 resolver recognizes only that object through a private `WeakMap` and bypasses author-facing CSP/Trusted Types restrictions; ordinary page-created `TrustedScript` retains its previous restrictions. Other engines continue to use the string path. If the page replaces global `eval`, Mimic does not pass the privileged object to that function and leaves the subsystem cold until the original `eval` is restored.

A focused test with `require-trusted-types-for 'script'` and without `unsafe-eval` confirmed that WebGPU, WebGL, and audio load, that author-supplied string and `TrustedScript` eval are rejected, and that the internal object does not leak through a replaced `eval`. The existing `TrustedScript` semantics test also passed.

After the fix, a diagnostic **live** Mimic run sent two `/fo` requests and received a 730-character token. The eight fields of block 23 → 6 became arrays again, with the same lengths as Chrome; the partial signature mismatch for block 27 disappeared. Two clean runs without iframe modification also sent two POST requests each and received 730-character tokens, with no observed `600010`. The second clean run used the final binary, `SHA256 28F4FE62DBEC6527EE9A2FC547D9BA2E70E0080D6DAB55795C7D4EFF593F8255`. Its summary is stored locally in `.build/flickr-audit/vm-analysis/mimic-final-control-result.json`.

One unmatched Chrome block and differences in individual arrays and values remain when comparing successful Chrome and fixed Mimic sessions. Both sessions obtained tokens; these residual differences have not been established as browser-semantic defects. The leaf-difference count between independent sessions is not a health metric: it can even increase when new probes execute successfully.
