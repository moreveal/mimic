# Широкий аудит Chrome / Mimic — 2026-09-11

Аудит обнаружил несколько независимых системных групп отклонений. Следующий этап разумно строить вокруг этих групп с общим regression corpus, а не вокруг очередной ошибки одного сайта. Ни одно из перечисленных отличий само по себе не доказывает причину ответа удалённой антибот-системы.

Runtime в этом аудите не изменялся. База: `3faacc6`; свежая сборка `.build/mimic-audit.exe`, SHA256 `A80E2F47120B3B82C79C363F904707D5FE3DF1146E4304CBEE598EB63C86EEDC`. Эталон: Chrome **152.0.7977.82**, Windows, новый профиль, headful; дополнительные проверки — headless той же версии. Пробы выполнялись на localhost в отдельных тестовых процессах/контекстах. Это не проверка TLS/JA4 удалённого сайта.

## Что не объявляем подтверждёнными новыми runtime-багами

* `cross_realm_reflection`: оба браузера прерываются при нормализации результата, ошибки различаются. Сначала исправить диагностическую пробу; этот результат не доказывает конкретную reflection семантику.
* Четыре sweep-пробы требуют отсутствующий `#parsed-template`; исключены из валидного знаменателя. Последующие 119 connection failures после единственного native crash также не отдельные дефекты.
* connection.downlink 1.45 против 10 — различие среды/модели оценки. Точные resource durations и различающиеся UA headful/headless не основание для фикса на измеренное число.
* `<anonymous>` против `<eval>` / `__pyppeteer_evaluation_script__` в стеке требует сравнения одинаковой CDP source attribution, а не подмены JS exception semantics.
* Падение A01 произошло при фоновой сборке snapshot. Название находившейся в работе Performance timing and mark пробы не доказывает, что падение вызвал Performance.mark.

## Предлагаемый порядок пакетных работ

1. Воспроизвести A01 отдельным циклом создания/закрытия Pages и локализовать A02 на пути выполнения CDP/планировщика. Это диагностические foundations для остальных измерений.
2. Исправлять request context как единый механизм: redirect chain origin/site, cookies, CORS; одним corpus проверять GET/POST и типы redirects, credentials и чтение ответа.
3. Исправлять realm ownership как группу: retained old realm, borrowed methods, prototypes, construction. History structured clone — отдельная ограниченная задача.
4. Исправлять модель WebIDL bindings сразу матрицей: brands с учётом lenient-this, nonconstructible operations, placement и descriptors. Не реализовывать 223 stub getter ради галочки.
5. После повторного общего corpus переходить к CSS/layout/font метрикам. Missing APIs и маленькие PCM дельты оставить ниже по приоритету, пока workload не докажет необходимость.

Так один пакет изменений проверяется сразу против накопленного набора, а новый запуск целевого сайта становится контрольной точкой, а не способом искать каждую следующую ошибку.
